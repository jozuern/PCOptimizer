# Repository audit, 2026-10-10 (second pass)

Scope: the whole repository at commit 7d47763 (version 0.4.8), read only. No code was changed for this audit. This is the second audit of the day; the first one ([audit-2026-10-10.md](audit-2026-10-10.md), commit 20650b3) is the baseline, and its fixed items are not repeated.

Method: six area reviews ran in parallel:
- tweak engine and catalog;
- platform, interop and security plumbing;
- feature modules (startup, tools, apps, debloat, cleanup);
- hardware and findings;
- the WPF app;
- tests, build, CI and docs.

One cross-cutting review (architecture, coupling, duplication, dependencies) ran alongside them. I checked every high finding again by reading the cited code. I also spot-checked several medium findings: DoH exit codes, per-user MSI entries and the rundll32 uninstall command. Nothing was rated critical. Findings marked "(unconfirmed)" depend on Windows internals or real hardware and need a check in the VM. Where two reviews reported the same problem, it is listed once.

## Status after the fixes (same day)

Fixed, each with a test where the behavior can be tested in the sandbox: H1 to H7, M1 to M21 except M22, M23 to M25, and L1 to L3, L5 to L11, L13 to L17, L19 to L23 in the parts listed below. 685 tests pass, including the read-only Hardware tests. Notes on how:

- **H1:** the data folder is created with its locked permissions in one step; a folder or file that Administrators or SYSTEM do not own is moved aside and deleted, never given a new owner; `PrepareRoot` checks the protected DACL and fails closed.
- **H2:** `StartupHookSupport=false`; an elevated start with `CORECLR_ENABLE_PROFILING` set stops with a message; the protected restart drops runtime and profiler variables. SECURITY.md names the remaining profiler limit.
- **H3 and M2:** elevated tools get an admin-only TEMP below the data folder, `SystemRoot`, `windir` and `ComSpec` from Windows, and a PATH of Windows' folders plus only those machine PATH folders that only administrators can change. On this PC the machine PATH held user-writable folders (`C:\Python314`, a folder in a user profile).
- **H4:** backups that contain a value of the user's registry part or an accessibility shortcut live in `backups\users\<SID>` and record their owner; another account neither sees nor overwrites them.
- **H5 and M14:** every page operation that changes the system runs through `ChangeRunner.RunExclusiveAsync` (one change at a time, errors logged and shown): Debloat, Cleanup, uninstall, winget installs and Update all, quick fixes, DNS flush, Explorer restart, Winsock reset, update repair, recycle, SFC and DISM, PawnIO, the restore point switch. Self-update waits for any change or scan.
- **M4:** `CommandLine.Program` returns the program a line starts (rundll32 itself) with its arguments; `ImagePath` keeps returning the file to judge. The uninstaller runs elevated only when the program and the DLL are admin-only.
- **M7:** DISM and PowerShell reads of the app's process runner are shared for 20 seconds and dropped on write (`ReadCache`); test fakes never cache.
- **M12:** the update repair judges each step by the service state (`QueryServiceStatus`) instead of net.exe's exit code.
- **Found while fixing L8:** a runtime registry delete action (removing a priority rule) could not be stored with its backup, because its empty value could not be written as JSON. The value is now left out when empty; `ProgramPriority.RemoveTweak` has a test.

Not fixed, with the reason:

- **M22:** the V-Cache driver's service name (`amd3dvcacheSvc`) is named only by a community guide that could not be opened (HTTP 403); it needs a check on an X3D PC or in the VM.
- **M26:** resolved by the merge of the two branches.
- **L4:** the hibernation default needs a check in the VM.
- **L12:** a restart notice after DISM returns 3010 needs a "pending restart" path that capabilities do not have yet.
- **L9, partly:** drivers without `ImagePath`, services switched to Manual, per-user shell extensions and space-separated Load and AppInit paths are still open; 32-bit files, ANSI paths, the WMI timeout and the per-user Winlogon Shell are fixed.
- **L14, partly:** hard links still count as duplicates.
- **L18, partly:** the F2 threshold stays at 75 Hz (the 60 Hz panel case is unconfirmed, and a real 75 Hz monitor limited to 60 Hz should still be reported); four DDR5 modules on Intel need a sourced Intel limit; VMs are not detected for memory checks.
- **L21, partly:** `global.json` keeps `rollForward: latestPatch` (disable would break builds after any SDK patch update), and the runtime version test still reads the test host's runtime.

## Summary

The baseline is good:
- **Build and tests:** the build is clean (0 warnings) and 641 of 641 non-Hardware tests pass (656 including the read-only Hardware tests).
- **Real PC:** no test reaches a real adapter.
- **Layering:** Core has no UI dependencies.
- **Catalog:** 212 unique tweak ids, conflicts listed on both sides, every Expert or boot-critical tweak is a preview, and every undocumented tweak is a preview or has proof. The 275 EN and 275 DE pages are paired.
- **Strings and XAML:** EN and DE resx have the same keys and placeholders, and there are no typography violations or WPF-UI gotchas.
- **Licenses and P/Invoke:** licenses match the shipped packages, and P/Invoke layouts match the headers.

Most items from the morning audit are fixed: H1 to H4, H10, M3 to M8, M18 to M21 and M27 to M32.

The remaining risk sits in four places:

1. **Elevation boundary, again.** Three gaps remain:
   - the data folder can adopt files planted while it is being created;
   - the elevated app itself still honors .NET startup hooks and profiler variables from the user's environment;
   - elevated child tools (DISM, winget, uninstallers) still use the user's `%TEMP%`.

   Per-user uninstall entries can also trigger an elevated `msiexec /x`.
2. **Shared PCs.** Backups of user settings (HKCU values, accessibility shortcuts) are keyed by tweak only, not by user. A second Windows account sees the first account's backup as its own.
3. **Page operations outside the change pipeline.** Debloat, Cleanup, the uninstaller, winget, quick fixes, the update repair and PawnIO change the system without the "one change at a time" gate. Many of these commands also have no catch.
4. **New feature code** has rough edges:
   - "Recycle" can delete permanently.
   - The startup scanner can be blinded by one bad value.
   - The update repair and IP renew can report success or leave the PC offline.
   - rundll32-based uninstall commands do not work.

## Top 5 refactors

### 1. Finish the change pipeline for page operations (about 1 day)

Covers H5, M14, M19 and part of M15.
1. Make `ChangeRunner.RunExclusiveAsync(string what, Func<Task> work)` public and add `PageViewModel.RunWorkAsync`. That method sets `IsWorking`, takes the gate, catches, logs and reports with Error severity.
2. Route Debloat, Cleanup, uninstall, winget, quick fixes, update repair, PawnIO, the restore point toggle and the self-update through it.
3. Move flush DNS, Winsock reset and Explorer restart into `QuickFixes.All` so they have sources and tests.

Result: the documented "one change at a time" rule becomes true, and every failure is logged and shown the same way.

### 2. Close the remaining elevation gaps (about 1 day)

Covers H1, H2, H3, M1, M2 and M3.
1. Create the data folder atomically with its security descriptor, never adopt unverified children, and fail closed.
2. Turn off startup hooks, and strip runtime and profiler variables from the restarted process.
3. Build child environments from an allow-list, with an admin-only TEMP.
4. Run per-user MSI entries de-elevated.
5. Map generic rights in `TrustedPath`.

Add tests in `SecurityTests` for each item.

### 3. Per-user backups and locked backup files (about 1 day)

Covers H4, M5, L1, L2 and L7.
1. Add the hive owner's SID to user-scope target keys (with a read fallback for old keys).
2. Distinguish "no backup" from "backup unreadable".
3. Drop cleanly rolled-back entries, prefer stored actions on undo, prune exports, and set the owner on new files.

Add sandbox tests that run apply and undo as two different SIDs.

### 4. One command-line model and one process runner (about 1.5 days)

Covers M4, M6, M7, M9, M10, M12, M13, L11 and the duplication the cross-cutting review found:
- the DISM wrappers in `OptionalFeatures` and `Capabilities`;
- two Uninstall-key readers;
- `StreamingProcess` users that cannot be faked;
- raw WMI calls without a timeout.

Steps:
1. Separate "program to run" from "file to judge" in `CommandLine`.
2. Add `IProcessRunner.RunStreamingAsync` with OEM decoding and a deadline that covers the pipes.
3. Write one DISM helper (run, parse table, exit codes).
4. Check service state instead of exit codes.
5. Cache expensive reads per detection pass.

Since the morning `MainViewModel.cs` grew from 1001 to 1232 lines and `PageViewModels2.cs` from 909 to 1289 (five page view models plus rows).
