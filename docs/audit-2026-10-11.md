# Repository audit, 2026-10-11

Read-only audit of `main` at `60c3a93`. No code was changed.

## Method

Six area reviews ran in parallel, file by file, plus one cross-cutting review:

| Area | Scope |
|---|---|
| Change engine | `Core/Actions`, `Core/Tweaks`, `Core/Backup` |
| Platform and startup | `Core/Platform`, `Interop`, `Startup`, `Updates`, `Logging`, `Network`, `Services`, `Profiles` |
| Detection and advice | `Core/Hardware`, `Core/Findings`, catalog data used by checks |
| Tools and catalog | `Core/Tools`, `Cleanup`, `Debloat`, `Apps`, `Docs`, catalog JSON, 550 explanation pages |
| App | `src/Optimizer.App` (view models, views, services, resources, manifests) |
| Tests, build, compliance | `tests/`, csproj and props, workflows, hooks, scripts, licenses, PRIVACY, notices |
| Cross-cutting | layering, coupling, duplication, policy consistency, dependencies, dead code |

I re-checked every critical and high finding against the code before including it. Two were downgraded after
verification (noted inline). Medium and low findings come from the area reviews; the ones I also checked are marked
"verified". Items the reviewers could not confirm are marked "unconfirmed".

Build and tests at audit time: `dotnet build -c Release` 0 warnings, 0 errors; `dotnet test -c Release --no-build
--filter "Category!=Hardware"` 734 passed, 0 failed.

## Summary

The codebase is in good condition for an elevated system tool. The transactional engine, backup format, update
signing, PresentMon extraction, cleanup deletion, link handling and P/Invoke layouts held up under review, and the
catalog and all 275 EN/DE page pairs pass every structural rule in CLAUDE.md. No critical findings.

There are six high findings:

- Two are elevation-boundary gaps where the elevated process still trusts something a standard-user process controls:
  cmd AutoRun, and the Recycle path race.
- One is a license compliance gap: LGPL modules ship inside a dependency.
- One check never works in the app: F21.
- One common UI flow is broken: switching DNS presets.
- One advisor check gives a fix that does not exist on a common class of PCs: A.xmp.

The main structural risk is that the "tests never touch the real PC" rule is held by convention outside the engine,
and that `MainViewModel` sequences too much (scan, gate, rebuild) for its ordering bugs to be obvious.

### High

**H1. Elevated uninstallers run the user's cmd AutoRun.**
`src/Optimizer.Core/Apps/Programs.cs:118-123`, `:138-141`; `src/Optimizer.Core/Platform/ProcessHardening.cs`
(no AutoRun handling). Verified.

- **Problem:** `cmd.exe` is in `CommandLine.ScriptHosts`. An uninstall string such as `cmd /c "C:\Program
  Files\X\u.bat"` whose files are admin-only is classified `Elevated`. So is a bare `.bat`, because it is neither a
  host nor a launcher, and CreateProcess runs it through `cmd.exe /c`. In both cases cmd runs
  `HKCU\Software\Microsoft\Command Processor\AutoRun`. Under the usual split-token admin, that is the same hive any
  medium-integrity process can write.
- **Scenario:** Malware running as the user sets AutoRun. The user uninstalls a program with a batch uninstaller
  from the Apps page, and the malware command runs with full admin rights.
- **Fix:**
  - Start cmd hosts with `/D`, and wrap `.bat`/`.cmd` files as `cmd.exe /D /C "<file>"`.
  - Or run batch uninstallers `AsUser`.
  - Add a test that `Command()` never returns an elevated cmd line without `/D`.

**H2. Race between the check and the elevated Recycle Bin move in the Storage analyzer.**
`src/Optimizer.Core/Tools/StorageAnalyzer.cs:225-236`, `src/Optimizer.Core/Platform/SafeDelete.cs:39-52`. Verified.

- **Problem:** `ResolvesToItself(p)` opens a handle, compares the final path and closes the handle. Then
  `SHFileOperation` resolves the same path string again, elevated.
- **Scenario:** A user-writable parent in Downloads is swapped for a junction between the check and the move. An
  admin-writable file is then moved to the bin with admin rights, for example a third-party boot driver. The
  attacker can retry in a loop until the timing works.
- **Fix (preferred):** Recycle de-elevated, as the session user. That also removes the "wrong account's Recycle
  Bin" case.
- **Fix (minimum):** Hold handles on every parent folder without `FILE_SHARE_DELETE` from the check until
  `SHFileOperation` returns.

**H3. LGPL-2.1 PawnIO modules ship inside the exe, and the notices say they are not shipped.**
`docs/THIRD-PARTY-NOTICES.md:27`, `src/Optimizer.App/Licenses/licenses.json:109-117`. Verified.

- **Problem:** `LibreHardwareMonitorLib.dll` 0.9.6 embeds 12 compiled PawnIO modules as resources, including in
  `runtimes/win-x64/lib/net10.0`: `IntelMSR`, `RyzenSMU`, `SmbusI801`, `AMDFamily17` and others. The notices table
  lists the modules as LGPL-2.1 under "installed only on request, not shipped". The LGPL text is not in
  `Licenses/`, and no source offer is given.
- **Fix:**
  - Add `lgpl-2.1.txt`.
  - Add a licenses.json entry "PawnIO modules (embedded in LibreHardwareMonitorLib)" with its source URL.
  - Move the row into the shipped table.
  - Make the license test fail when the LHM version changes, so embedded resources get re-reviewed.

**H4. F21 (`LeftoverCheck`) is always Unknown in the app.**
`src/Optimizer.Core/Findings/FindingEngine.cs:39`. Verified.

- **Problem:** `CreateChecks(registry, bcd)` builds `new LeftoverCheck()` without `bcd`, so the reader is always
  `() => null`. The app passes `services.BcdElements` (`MainViewModel.cs:832`, `:884`), but it never arrives. Unit
  tests construct the check directly, so they miss it.
- **Fix:** Use `new LeftoverCheck(bcd)`, and add a `FindingEngine`-level test that passes a BCD reader through.

**H5. Switching from one app-set DNS preset to another undoes the first and refuses the second.**
`src/Optimizer.App/ViewModels/PageViewModels.cs:262-270`, `MainViewModel.cs:170`, `:1137-1163`, `:796-799`,
`Services/ChangeRunner.cs:84`. Verified.

- **Problem:**
  1. `UndoAsync` raises `Changed` in its `finally`. The async handler runs synchronously up to
     `ScanOnceAsync`, which sets `IsScanning = true`, so `ChangeGate.Scanning` turns on.
  2. `ChooseDnsAsync` then calls `ApplyAsync`.
  3. `ExclusiveAsync` sees `CanChange == false` and reports "Change_Busy".
- **Scenario:** Cloudflare was set by the app and the user picks Google. DNS falls back to automatic, Google is
  never applied, and the user is told another change is running.
- **Fix:** Add a `ChangeRunner.ReplaceAsync(undo, apply)` that runs both inside one `ExclusiveAsync` and raises
  `Changed` once. Or await `Owner.ScanAsync()` after the undo before applying.

**H6. A.xmp tells users to enable XMP where the board cannot run above CPU spec.**
`src/Optimizer.Core/Findings/Checks/MemoryStorageChecks.cs:94-109`. The code was verified; the hardware limit is
documented Intel behavior.

- **Problem:** Any configured speed below the rated speed is a Problem with impact 4 and BIOS steps. Intel 8th to
  10th gen on non-Z chipsets (H310/B360/B365/H370/H410/B460/H470) cap memory at the CPU's spec (2666 or 2933), and
  XMP cannot raise it.
- **Scenario:** An i5-9400F on a B365 board with a DDR4-3200 kit is told to enable XMP and loses score for a fix
  that does not exist. This is a common prebuilt configuration.
- **Fix:**
  - When the configured speed equals the CPU's official maximum and the board is not a Z model, or its chipset is
    unknown on these generations, return Info with a `locked` variant.
  - State the limit on both explanation pages with an Intel source.

### Medium

Change engine:

- **M1. Undo of a power plan tweak can delete a plan the app did not create.** `src/Optimizer.Core/Actions/SystemActions.cs:157-161`, `:180-225`. Verified.
  - **Problem:** `Target()` reuses any existing plan with the PCOptimizer name. `RestoreIfUnchanged` then deletes that GUID because it is not built-in and not the original.
  - **Scenario:** A plan left over from a cleared data folder, a Debug run, or a user's customized plan with that name is deleted.
  - **Fix:** Record at apply time whether this apply created the plan (for example `Data = "created:{guid}"`), and delete only such plans.
- **M2. `not` conditions match when the fact is unknown.** `src/Optimizer.Core/Tweaks/Condition.cs:32`. Verified.
  - **Problem:** `!Not.Evaluate(facts)` is true for unknown facts, which contradicts "unknown facts never match".
  - **Scenario:** With `os.edition` unknown, policy tweaks gated by `not.in [Core...]` are offered on Home, where they read as Applied but have no effect.
  - **Fix:** `return Not.CanEvaluate(facts) && !Not.Evaluate(facts);`.
- **M3. Another account can delete or overwrite a remaining shared backup.** `src/Optimizer.Core/Backup/BackupStore.cs:139`, `:159`, `:202-215`; `TweakEngine.cs:541-543`.
  - **Problem:** `Owner` is never cleared when a partial revert leaves machine-only entries in the shared folder. Another account then sees "no backup", applies again, and records the applied value as the original.
  - **Fix:**
    - Clear `Owner` when no per-user entries remain.
    - Never delete or overwrite a shared file owned by another SID.
    - Block apply while another account's backup exists for the tweak.
- **M4. A damaged backup that cannot be quarantined counts as "no backup".** `BackupStore.cs:156-159`, `:234-247`.
  - **Problem:** If `Quarantine` fails (for example antivirus holding the file), `Get` returns null.
  - **Scenario:** Undo "succeeds" without restoring anything, and the next apply overwrites the originals.
  - **Fix:** `Quarantine` returns bool, and on failure `Get` throws `BackupUnreadableException`.

Elevated file operations:

- **M5. Elevated Start menu shortcut write and delete in a user-controlled folder.** `src/Optimizer.Core/Platform/StartMenuShortcut.cs:45-67`, called from `MainViewModel.cs:675-689`. Verified. Three reviewers raised this; I downgraded it from high because the file name and content are fixed.

  - **Fix:** Create and delete the shortcut de-elevated. At minimum, call `SafeDelete.HasNoLinks(folder)` and check the folder owner, and delete through `SafeDelete`.
- **M6. A failed self-update install can leave a truncated exe.** `src/Optimizer.Core/Updates/Updater.cs:82-96`.
  - **Problem:** `File.Copy` over the running path can fail partway. The rollback `Move(.old, running)` then throws because the target exists, and the good exe stays as `.exe.old`.

  - The same code also needs the link check from M5.

## Verified sound

These were reviewed and found correct. Keep them as they are.

- **Engine:**
  - The first-original rule holds, and the backup is written durably before the first write.
  - Rollback covers the action that failed.
  - Key-absent and value-absent are tracked separately.
  - Power settings restore mains and battery separately.
  - Shared bit and token values touch only their own bits.
  - File names from tweak ids and SIDs are sanitized.
- **Updates:**
  - ECDSA P-256 signature over the version and the hash.
  - HTTPS only, canonical asset URLs, admin-only download folder.
  - The file is held open from the hash check until it starts, and a missing key fails closed.
- **Cleanup and Debloat:**
  - Cleanup deletes through a handle after a final-path check and never enters reparse points.
  - Debloat works from an allowlist, and OneDrive removal runs de-elevated with redirection guards.
- **PresentMon:** pinned SHA-256 that matches the vendored exe, extracted to the admin-only tools folder, held without write sharing.
- **Interop:** struct layouts match the SDK headers, and no handle leaks were found.
- **Data and privacy:** `DataPaths.Root` is used consistently, there is no telemetry, and network use is opt-in and listed in PRIVACY.
- **UI rules:** EN and DE resx match (578 keys each, placeholders checked). All 49 `SymbolRegular` names exist, and no Appearance or ListViewItem gotchas or forbidden characters were found.
- **Catalog:** all 212 tweaks follow the preview, proof and Expert rules, and all 275 page pairs pass the summary, sources and character rules.
- **CI:** first-party actions are pinned to SHAs, no `pull_request_target`, least-privilege tokens, locked restore. The signing key is used only in a job that runs no project code.
