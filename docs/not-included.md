# Tweaks that are not included

PCOptimizer only offers a tweak when the setting is documented and the evidence supports what it promises. This page lists popular tweaks that the app does not offer, or no longer offers, and why. If you applied one of the removed tweaks with an earlier version, it still shows on the Changes page as "Removed tweak" and Undo restores your original values.

Every source below was opened and checked for the claim it is cited for.

## Removed in 0.4

| Tweak | Why it is not included | Sources |
|---|---|---|
| MMCSS game profile (`latency.mmcss`: GPU Priority, Priority, Scheduling Category, SFIO Priority, SystemResponsiveness) | Microsoft documents GPU Priority as "not yet used" and SFIO Priority as "not used", and Priority is "always treated as 2" when Scheduling Category is High. Of five values, only SystemResponsiveness and Scheduling Category do anything, and only for threads that register with MMCSS. No measurement shows a gain in games. | [MMCSS](https://learn.microsoft.com/en-us/windows/win32/procthread/multimedia-class-scheduler-service) |
| Win32PrioritySeparation = 0x26 (`latency.win32PrioritySeparation`) | 0x26 is exactly the value Windows writes for "Adjust for best performance of: Programs" and means the same as the client default 2: short, variable time slices with a 3:1 foreground boost. The tweak changes nothing on Windows 11. | [Win32PrioritySeparation](https://learn.microsoft.com/en-us/previous-versions/cc976120(v=technet.10)) |
| Dynamic tick off (`latency.disableDynamicTick`, bcdedit disabledynamictick) | Microsoft says this boot option "should only be used for debugging". No reliable measurement shows a benefit in games, and it touches the boot configuration. | [BCDEdit /set](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/bcdedit--set) |
| Global timer resolution requests (`latency.globalTimerResolution`, GlobalTimerResolutionRequests) | Microsoft does not document this registry value. Its timeBeginPeriod documentation describes the per-process timer behavior since Windows 10 2004 and warns that higher resolutions reduce performance and power saving. | [timeBeginPeriod](https://learn.microsoft.com/en-us/windows/win32/api/timeapi/nf-timeapi-timebeginperiod) |
| Spectre and Meltdown mitigations off (`security.mitigationsOff`) | Microsoft measured single-digit slowdowns that most users do not notice on Skylake and newer processors, and Windows 11 only supports newer ones. The value also turns off other speculative execution protections. A real security loss for a gain too small to notice. | [Microsoft Security blog](https://www.microsoft.com/en-us/security/blog/2018/01/09/understanding-the-performance-impact-of-spectre-and-meltdown-mitigations-on-windows-systems/), [KB4073119](https://support.microsoft.com/en-us/topic/kb4073119-windows-client-guidance-for-it-pros-to-protect-against-silicon-based-microarchitectural-and-speculative-execution-side-channel-vulnerabilities-35820a8a-ae13-1299-88cc-357f104f5b11) |
| SmartScreen for apps off (`security.smartScreenOff`) | No effect on games. It only removes a check of downloaded programs. | [Policy CSP SmartScreen](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-smartscreen) |
| Remove OverlayTestMode (`leftover.overlayTestMode`) | It treated OverlayTestMode = 5 as a broken leftover. NVIDIA's own support article ships exactly this value to turn off multiplane overlay on Windows 11, so it is not a leftover. The MPO tweak now uses it. | [NVIDIA a_id 5157](https://nvidia.custhelp.com/app/answers/detail/a_id/5157) |
| Fullscreen optimizations off, global (`gpu.fullscreenOptimizationsOff`, GameDVR_FSE values) | Microsoft does not document the GameDVR_FSE values. Microsoft measured fullscreen optimizations as equal to or better than exclusive fullscreen for almost all users. The documented opt-out is per game: the exe's Properties > Compatibility > "Disable fullscreen optimizations". | [DirectX blog](https://devblogs.microsoft.com/directx/demystifying-full-screen-optimizations/) |
| Teredo off (`network.teredoOff`) | Teredo has been turned off by default since Windows 10 1803, so the tweak usually changes nothing, yet it showed as "not applied". Values of DisabledComponents other than 0 and 32 can break Routing and Remote Access. | [Deprecated features](https://learn.microsoft.com/en-us/windows/whats-new/deprecated-features) |
| Short 8.3 file names off (`storage.8dot3Off`) | Windows already creates no short names on volumes other than the system volume by default. On the system volume Microsoft keeps them because some programs need them. The setting only affects new files and has no effect on games. | [fsutil 8dot3name](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/fsutil-8dot3name) |
| Handwriting data sharing off (`privacy.handwritingSharingOff`) | Both values exist in current Windows only inside the policy "Restrict Internet communication". Microsoft does not document them on their own for Windows 11, so their effect is not confirmed. | none found |
| Windows Platform Binary Table off (`privacy.wpbtOff`, DisableWpbtExecution) | Microsoft's WPBT specification does not mention this value, and Microsoft does not document it anywhere else. | [WPBT specification](https://download.microsoft.com/download/8/A/2/8A2FB72D-9B96-4E2D-A559-4A27CF905A80/windows-platform-binary-table.docx), [Eclypsium](https://eclypsium.com/2021/09/20/everyone-gets-a-rootkit/) |
| Print Spooler on Manual (`services.spoolerManual`) | The Print Spooler has no start trigger (checked with `sc qtriggerinfo Spooler` on Windows 11), so on Manual it does not start when you print: printing, including Print to PDF, stops working. No effect on games. | [ChangeServiceConfigW](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-changeserviceconfigw) |
| Core parking off (`power.coreParkingOff`) | On desktops the Balanced plan already keeps all cores unparked on mains power. Where the value is lower, the processor vendor usually set it, and Microsoft advises to ask the silicon vendor before changing it. On hybrid processors the setting misses the performance cores (CPMINCORES1). No measurement shows a gain in games. | [CPMinCores](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/options-for-core-parking-cpmincores), [Power performance tuning](https://learn.microsoft.com/en-us/windows-server/administration/performance-tuning/hardware/power/power-performance-tuning) |
| Minimum processor state 100 % (`power.minProcessorState100`) | Microsoft documents this only for servers that need very low latency or a fixed frequency. The High performance plan, which the gaming plan copies, already sets 100 % on mains power, and the setting misses the performance cores on hybrid processors. | [Power performance tuning](https://learn.microsoft.com/en-us/windows-server/administration/performance-tuning/hardware/power/power-performance-tuning), [MinPerformance](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/options-for-perf-state-engine-minperformance) |

## Never included

| Tweak | Why it is not included |
|---|---|
| NVIDIA settings outside the public NVAPI headers (for example forced Resizable BAR or settings only NVIDIA Profile Inspector shows) | The app only reads and writes driver settings that NVIDIA documents in NvApiDriverSettings.h. |
| TCPNoDelay under the network interface keys | Microsoft documents TcpAckFrequency for the TCP/IP stack, but not TCPNoDelay. Programs turn off Nagle's algorithm per connection themselves. The delayed acknowledgement tweak sets only TcpAckFrequency. |
| Disabling Windows Defender, Windows Update or the firewall | They protect the PC, and turning them off has no documented gaming benefit. |
