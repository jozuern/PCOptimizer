# Repository audit, 2026-10-10

Scope: the whole repository at commit 20650b3 (version 0.4.0), read only. No code was changed for this audit.

Method: six area reviews ran in parallel (core engine; platform, interop and I/O; hardware and findings; WPF app; catalog content and docs; build, CI, tests and licenses), plus one cross-cutting review (architecture, coupling, duplication, dependencies). Every high finding below was then checked again by reading the cited code. Nothing was rated critical. Findings marked "(unconfirmed)" depend on behavior that cannot be proven from the source alone (real hardware, Windows internals) and need a check in the VM.

## Summary

The project is in good shape for its size (about 43,000 lines plus 300 explanation pages):

- **Build and tests:** the build is clean (0 warnings) and all 377 non-Hardware tests pass.
- **Layering:** Core has no UI dependencies, and actions only touch the system through `ActionContext`, so the sandbox and fakes are used consistently.
- **Content:** catalog content is consistent. EN and DE pages are paired 150/150, every page has its sections and sources, and source URLs match between languages.
- **Security:** most of the defenses hold. Deletes are handle-based with a final-path check, winget comes from a trusted path, ids are allow-listed before reaching a command line, and the vendored PresentMon is hash-pinned. P/Invoke struct layouts match the Windows headers. No telemetry was found, and all network use matches `docs/PRIVACY.md`.

The remaining risk sits in four places:

1. **Elevation boundary.** Two gaps break the "never run anything from user-writable paths" rule: elevated PowerShell auto-loads modules from the user's Documents folder, and an environment variable switches off the protected native-runtime restart. The self-updater only checks a checksum from the same release, which proves the download is intact but not who published it.
2. **Apply/undo failure paths.** An action that fails half-way is not rolled back, and its backup can be dropped. Undo comparisons are all-or-nothing across AC/DC sides and NIC keywords. A corrupt backup file silently loses the true original.
3. **App concurrency and threading.** Apply runs on the UI thread. Scans and changes can overlap because nothing is disabled while busy. The "Apply again" button runs Undo. A failed undo tells the user "Nothing was left half-changed".
4. **Two memory checks give wrong results** on common hardware: DDR5 at 3600 MT/s is read as MHz, and Intel's `Controller0/1-ChannelA` locators look like a single channel.

Tests also break the CLAUDE.md rule against touching files outside a temp folder. They write session logs into the real `%LocalAppData%\PCOptimizer\logs` and leave `C:\pco-test-*` folders behind; 52 were found on this PC.

### Medium

Security and release:

- **M1** `.github/workflows/release.yml:11-12,28-29,42-49`. The `contents: write` token covers the whole job, and `actions/checkout` keeps it in `.git/config` (`persist-credentials` defaults to true) while restore, build and test run third-party package code. A poisoned dependency could push to the repository or change other releases. Fix: a build job with `contents: read` and `persist-credentials: false` uploads the exe; a separate release job with `contents: write` only downloads it and runs `gh release create`.
- **M2** `src/Optimizer.Core/Tools/StorageAnalyzer.cs:177-188`. `Recycle` checks only the path string, then calls `SHFileOperation` elevated, without `SafeDelete.HasNoLinks` or a final-path check. A parent folder swapped for a junction between scan and confirm sends a system file to the Recycle Bin. Fix: check each file with the same handle-based final-path test SafeDelete uses, or recycle from a de-elevated process.
- **M3** `src/Optimizer.Core/Platform/NativeLibraryGuard.cs:50-56` (unconfirmed). For a plain DLL name that is in neither System32 nor a trusted folder, `Resolve` returns `IntPtr.Zero`, and the runtime's default probing (which includes the exe folder, often Downloads) takes over. Fix: throw `DllNotFoundException` instead of falling back.
- **M4** `src/Optimizer.Core/Backup/BackupStore.cs:114-120,189-190` (unconfirmed). `Save` never sets an owner, while `Trusted()` accepts only Administrators or SYSTEM. If the elevated token's default owner is the user (EnableLUA=0, built-in Administrator, Administrator protection), backups are ignored at once and deleted on the next start. Fix: set the owner explicitly on the temp file before the move. Add an ownership check to the VM test plan.

Engine:

- **M5** `BackupStore.cs:98-104,122-133`, `TweakEngine.cs:244`. A corrupt backup reads as "no backup". A re-apply then records the already changed values as the original and overwrites the file. `Save` does not flush before the move, so a power loss after a BCD change can leave an empty file. Fix: `FileStream` with `Flush(true)`; rename unreadable files to `.corrupt` and block apply for that id.
- **M6** `TweakEngine.cs:126,278,333`. `a.Read(ctx)` runs unguarded at three places. A user-hive policy action on a managed PC without a loaded hive throws in `DetectState` and fails the whole scan, and at `:278` it aborts a batch after the restore point. Fix: use `SafeRead` there.
- **M7** `src/Optimizer.Core/Actions/ExtendedActions.cs:43-57`. `PowerModeAction` acts on the current power source only. Applied on battery and undone on mains, the backup is archived as "reset by Windows" and the battery overlay stays changed. Fix: store the source in `StoredValue.Data` and restore or compare only on that source.
- **M8** `SystemActions.cs:83-90`, `TweakAction.cs:77`. "Still applied" is all-or-nothing per entry, for AC/DC power settings and NIC keyword maps alike. If the user later changes only the AC value, the DC value is never restored and the backup is archived. Fix: compare and restore each side or keyword on its own.

The score bar (`OverviewPage.xaml:74,77`) and health disks are not refreshed even on a manual switch. Fix: subscribe to `ApplicationThemeManager.Changed`, or use DynamicResource-backed brushes.

## Top 5 refactors

Ranked by value for effort.

### 1. One change pipeline: off the UI thread, serialized, with uniform error handling

- **Goal:** fix H5, H6, H7 and H8 and M9 to M15 at their common root.
- **Files:** `ChangeRunner.cs`, `MainViewModel.cs`, `TweakItemViewModel.cs`, `PageViewModels.cs`, `PageViewModels2.cs`, `App.xaml.cs`, `Strings*.resx`.
- **Steps:**
  1. Make `ChangeRunner` the only entry for apply, undo, batch, undo all and scan.
  2. Guard it with one `SemaphoreSlim` and one reusable in-flight scan task.
  3. Run Detect, Preview and Apply through `Task.Run`, with the dialogs on the UI thread.
  4. Use one catch/log/report path that picks the right message (applied, not applied, undo incomplete, error).
  5. Expose `CanChange`, and bind every switch and action button to it.
  6. Register the `UnobservedTaskException` and `AppDomain.UnhandledException` handlers.
  7. Derive the row's action label and command from one method, which removes the Apply again/Undo mismatch.
- **Risk:** low to medium. Behavior changes only on the failure and concurrency paths.
- **What it enables:** a responsive UI during DISM and bcdedit, honest result messages, and no stale state from overlapping scans.

### 2. Close the elevation gaps in process and runtime startup

- **Goal:** fix H1, H2 and M3 and the low platform items around process launching.
- **Files:** `SystemApi.cs` (`SystemProcessRunner`), `StreamingProcess.cs`, `StabilityProbe.cs`, `SingleFileRuntime.cs`, `Program.cs`, `NativeLibraryGuard.cs`, `SecurityTests.cs`.
- **Steps:**
  1. Merge the three launchers into one `IProcessRunner` with a streaming variant, exposed through `ActionContext`.
  2. For every elevated launch, set `WorkingDirectory = System32`, pin `PSModulePath` for PowerShell, import modules by absolute path, set the stderr encoding, and handle tree-kill errors.
  3. Make the runtime restart decide by folder only, and fail closed when elevated.
  4. Make `NativeLibraryGuard` throw instead of falling back to the default search.
  5. Add tests that the runner sets these values, and update the restart test.
- **Risk:** low. The VM test plan should cover startup under classic UAC and Administrator protection.
- **What it enables:** the "never run anything from user-writable paths" rule is enforced in one place, and winget, sfc and DISM become fakeable in tests.

### 3. Transactional, per-part apply and undo with durable backups

- **Goal:** fix H4 and M4 to M8, plus the missing tests in M30.
- **Files:** `TweakEngine.cs`, `TweakAction.cs`, `SystemActions.cs`, `ExtendedActions.cs`, `BackupStore.cs`, `Fakes.cs`, `UndoTests.cs`.
- **Steps:**
  1. Let an action report the parts it changed: AC/DC sides, NIC keywords, service config steps.
  2. Roll back the failing action's own completed parts.
  3. Compare and restore per part.
  4. Store the power source for `PowerModeAction`.
  5. Write backups with flush and an explicit owner, and quarantine unreadable files while blocking apply for that id.
  6. Route the three unguarded `Read` calls through `SafeRead`.
  7. Add tests:
     - a fake action that writes and then throws;
     - a corrupt backup file;
     - hibernation and display mode apply/undo;
     - an AC-only drift.
- **Risk:** medium. This touches the core contract, but the sandbox tests cover it well.
- **What it enables:** undo can be called reliable after a failure, which is the app's main safety promise.

### 4. Catalog schema and integrity test

- **Goal:** fix M34, the content rule questions in H11 and M22 to M24, and the runtime-id inconsistencies.
- **Files:** `TweakDefinition.cs`, `TweakCatalog.cs`, `CatalogData.cs`, `Condition.cs`, `DocLint.cs`, `FactsBuilder.cs`, the runtime tweak factories, and a new `CatalogIntegrityTests.cs`.
- **Steps:**
  1. Set `UnmappedMemberHandling.Disallow`.
  2. Turn Verify, FormFactor, Basis, Media and registry Kind into enums.
  3. Add a `FactNames` registry that FactsBuilder writes, and check every `ReferencedFacts()` name against it.
  4. Check that `Requires`, `ConflictsWith` and `Fixes` ids exist, and that all label and dynamic resx keys exist in EN and DE.
  5. Let `blockedWhen` treat an unknown fact as "cannot check".
  6. Add a `RuntimeTweak.Create` helper that always uses `TweakIds.Slug`.
  7. Lint rules:
     - pages that say "not document" must belong to a tweak on an explicit allow list;
     - a tweak whose page says Undo does not restore something cannot be `reversible`.
- **Risk:** low. It may surface latent JSON typos at test time, which is the point.
- **What it enables:** catalog mistakes fail CI instead of silently turning into no-ops, and the "documented settings only" rule is enforced by a test, not by review.

### 5. Split MainViewModel and the page view model files, and add an App test project

- **Goal:** break up the god classes (`MainViewModel` handles navigation, scan, profiles, score, changes, banners, release check, self-update, language and links), and fix M33, M36 and the duplicated helpers.
- **Files:** `MainViewModel.cs` (1001 lines), `PageViewModels.cs`, `PageViewModels2.cs`, `App.xaml.cs`, `Updates/Updater.cs`, `HardwareReport.cs`, plus a new `tests/Optimizer.App.Tests`.
- **Steps:**
  1. Extract an UpdateViewModel and move the `CanSelfUpdate` policy into `Updater`.
  2. Extract a ChangesViewModel, a recommendations and profile state class, and a shell view model for navigation and the result toast.
  3. Give each page view model its own file.
  4. Add a ThemeService that raises one event every view model listens to (this also fixes M12 and M17).
  5. Introduce `DataPaths` subpaths, a `Format.Bytes` helper and an `AppInfo.Version` helper.
  6. Move HardwareReport labels to `labels.json`.
  7. Add App tests for `ChangeRunner` and the row state logic.
- **Risk:** medium. XAML binding paths reference `MainViewModel` and need updating. Use `--screenshot` in both themes and both languages, and `--perf` before and after.
- **What it enables:** testable UI logic and smaller rebuilds, and H5 and H6 class bugs get caught by tests.
