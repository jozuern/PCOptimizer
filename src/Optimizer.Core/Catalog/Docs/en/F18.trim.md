# TRIM disabled for SSDs

## Summary
::: status Problem
TRIM is turned off. Without it, an SSD does not learn which data was deleted, and write speed can drop over time.
:::
::: status Ok,Unknown,Info,Unsupported
Checks that Windows sends TRIM commands to SSDs, which keeps their write speed up.
:::

## Why it matters
When you delete a file, Windows only marks the space as free. TRIM tells the SSD which blocks are no longer needed, so the SSD can erase them in the background. Without TRIM the SSD has to do that work during later writes, which slows down installs and game updates and adds wear. For NTFS, TRIM is on by default unless an administrator turns it off [1]; it is usually only off after a tweak tool or an old guide turned it off.

## How we detected it
We read `DisableDeleteNotification` under `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem`. The value 0 means TRIM is on, 1 means off. If the value does not exist, TRIM is on, because that is the NTFS default [1]. This is the same setting that `fsutil behavior query DisableDeleteNotify` shows for NTFS. The check covers NTFS drives only; ReFS volumes (for example a Dev Drive) have their own setting, which we do not read.

## How to fix
1. Open a terminal as administrator.
2. Run `fsutil behavior set DisableDeleteNotify 0`.
3. Run **Defragment and Optimize Drives** for each SSD once, which sends a full retrim.

Or use **Fix** at the top of this panel: the app makes the change for you and can undo it later.

## How to check the fix
Run the scan again. TRIM should be shown as on.
